# InsurAgent

כלי עזר מבוסס AI שעוזר לאנשים פרטיים להכין בעצמם תביעות להחזר הוצאות רפואיות. המשתמש מספר איזה טיפול עשה ואיזה ביטוח יש לו, והכלי:

1. בונה רשימת מסמכים נדרשים (מתוך מאגר תבניות לפי חברה וסוג תביעה).
2. בודק את המסמכים שהמשתמש מעלה ומשייך אותם לדרישות. מסמכים מתביעות קודמות, כמו ת"ז ואישור בנק, נשמרים לשימוש חוזר.
3. מה שחסר, הופך למשימה למשתמש (לצלם, לחתום, לשלוח מייל שכבר הוכן) ומזכיר לו עד שהמשימה בוצעה.
4. כשהכול מוכן, בונה במכשיר של המשתמש קובץ PDF להגשה: טופס פרטי תביעה חתום וכל המסמכים.

**המשתמש מגיש ושולח הכול בעצמו.** הכלי לא מגיש, לא מייצג, לא מעריך סכומי החזר ולא קובע מה מכוסה.

## ארכיטקטורה

| רכיב | טכנולוגיה |
|---|---|
| אתר | React + Vite (RTL, מותאם לנייד), Firebase Hosting |
| התחברות | Firebase Auth (Google) |
| שרת / API | Hono על Cloud Functions (דור 2), נתיב `/api/**` דרך Hosting |
| נתונים | Firestore. הדפדפן מאזין לנתונים שלו בלבד, וכל כתיבה עוברת דרך השרת |
| סוכן | Claude Opus 5.5 עם tool use |
| תזכורות | פונקציה מתוזמנת שרצה כל שעה |
| קבצי מסמכים | **במכשיר של המשתמש** (IndexedDB), מאחורי ממשק `DocumentStore` שאפשר להחליף |

## פיתוח מקומי

דרישות: Node 22 ו-Java 11 ומעלה (בשביל אמולטור Firestore). Firebase CLI נדרש להעלאה בלבד.

```bash
npm install
cp server/.env.example server/.env   # להכניס ANTHROPIC_API_KEY
npm run dev                          # אמולטורים של Firebase + שרת + אתר
```

- האתר: http://localhost:5173. בנייד פותחים את הכתובת ברשת המקומית ש-Vite מדפיס.
- ממשק האמולטורים (משתמשים ונתונים): http://127.0.0.1:4000
- ההתחברות המקומית היא דרך אמולטור Google: בוחרים "Add new account" ומקלידים כל מייל.
- הנתונים המקומיים נמחקים כשמכבים את האמולטורים.

### הדגמה

`npm run samples -w server` יוצר בתיקייה `samples/` ארבעה מסמכים בדויים: קבלה, פירוט טיפולים, ת"ז ואישור בנק. כולם מסומנים "לדוגמה בלבד". הסוכן מזהה שאלה מסמכי דוגמה, וימשיך רק אם אומרים לו שזו הדגמה.

## העלאה לאינטרנט (Firebase)

הגדרה חד-פעמית:

1. ב-[Firebase Console](https://console.firebase.google.com): ליצור פרויקט ולעבור לתוכנית **Blaze**. Cloud Functions וקריאות ל-Claude דורשים אותה, ובהיקף קטן העלות צפויה להיות $0. מומלץ להגדיר התראת תקציב.
2. **Firestore Database**: ליצור מסד בתצורה Production, ולבחור מיקום באירופה (למשל `eur3`).
3. **Authentication > Sign-in method**: להפעיל את Google.
4. בטרמינל:
   ```bash
   firebase login
   firebase use --add            # לבחור את הפרויקט; מעדכן את .firebaserc
   firebase functions:secrets:set ANTHROPIC_API_KEY
   ```

בכל עדכון:

```bash
npm run deploy
```

הפקודה בונה את האתר, אורזת את השרת לתיקייה `server/deploy/` ומעלה את Hosting, Functions, חוקי Firestore והאינדקסים.

**הערות:**
- בקשות ל-API חוזרות מיד. עבודת הסוכן נכנסת לתור ב-Firestore (`claims/*/inbox`), ופונקציית `agent` מריצה אותה ברקע עד 9 דקות. הסיבה: Firebase Hosting מנתק בקשות אחרי 60 שניות.
- פונקציית הסוכן רצה עם `maxInstances: 1`, כי הנעילה שמונעת מהסוכן לרוץ פעמיים על אותה תביעה נמצאת בזיכרון. לפני שגדלים, צריך להעביר אותה ל-Firestore.
- Firestore צריך להיות במיקום שמתאים לאזור הפונקציות: `eur3` או `europe-west1`.
- **מכסות יומיות** (לפי שעון ישראל, על מה שעולה קריאות למודל):
  - **למשתמש:** 30 הודעות לסוכן ו-20 העלאות מסמכים.
  - **לכל המשתמשים יחד:** 300 הודעות ו-200 העלאות. זו תקרה שמגנה על התקציב.
  - **שינוי:** ב-[server/.env.functions](server/.env.functions), ואחריו `npm run deploy`. ההגדרות האלה לא סודיות ונשמרות ב-git.
- האזור של הפונקציות הוא `europe-west1` (ב-[server/src/functions.ts](server/src/functions.ts) וב-[firebase.json](firebase.json)).
- מפתח ה-API נשמר ב-Secret Manager. מעבר ל-Workload Identity Federation (בלי מפתח) אפשרי בהמשך, אבל דורש רכיב שמושך טוקן מהשרת של Google.

## גרסת ניסיון ומגבלת תיקים

- **מגבלה:** כל משתמש יכול לפתוח תיק אחד (`FREE_CLAIM_LIMIT` ב-[server/.env.functions](server/.env.functions)). השרת אוכף את המגבלה, ומי שהגיע אליה רואה כפתור וואטסאפ במקום תיבת תביעה חדשה.
- **הגדלה למשתמש מסוים:** ב-Firestore, במסמך של המשתמש תחת `users`, מוסיפים שדה `claim_limit` מסוג number, למשל 5.
- **פנייה לצוות:** וואטסאפ 055-660-2851 (מוגדר ב-[web/src/support.ts](web/src/support.ts)). הסוכן מפנה לשם שאלות שמעבר לתיק, בקשות לתיקים נוספים ותמחור.

## איפה נשמר מה

| מידע | איפה |
|---|---|
| קבצי המסמכים והחתימה | במכשיר של המשתמש (IndexedDB) |
| תוכן המסמך בזמן העלאה | עובר פעם אחת בשרת ובשירות ה-AI לצורך חילוץ פרטים, ולא נשמר |
| פרטים שחולצו מהמסמכים, פרטי תביעה, פרופיל, צ'אט, משימות | Firestore |
| ההיסטוריה הגולמית של הסוכן | Firestore (`claims/*/turns`), נגישה לשרת בלבד |
| חבילת ה-PDF להגשה | נבנית בדפדפן מהקבצים שבמכשיר |

**המגבלות של אחסון במכשיר:** החלפת מכשיר או ניקוי נתוני הדפדפן מוחקים את הקבצים. באייפון Safari עלול למחוק אחסון של אתרים שלא נכנסו אליהם זמן מה. אם קובץ חסר, הממשק מציג "לא שמור במכשיר הזה".

## מבנה

```
shared/                 רינדור PDF עברי (RTL), משמש את הדפדפן ואת סקריפט מסמכי הדוגמה
server/
  src/app.ts            ה-API (Hono): אימות טוקן, הסכמה, תביעות, מסמכים, משימות
  src/functions.ts      נקודת הכניסה ל-Cloud Functions (API + תזכורות מתוזמנות)
  src/dev.ts            שרת מקומי מול האמולטורים
  src/store.ts          שכבת הנתונים (Firestore)
  src/agent/            לולאת הסוכן, הכלים, ה-system prompt וחילוץ מסמכים
  knowledge/            תבניות דרישות לפי חברה וסוג תביעה (JSON)
web/                    React + Vite
firestore.rules         קריאה של נתונים עצמיים בלבד, בלי כתיבה מהדפדפן
```

## הסכמה ותנאים

כניסה ראשונה מחייבת אישור של תנאי השימוש ומדיניות הפרטיות, ואם הוגדר `ACCESS_CODE` ב-[server/.env.functions](server/.env.functions), גם את קוד הגישה (כרגע ריק: ההרשמה פתוחה). האישור נשמר עם גרסת הנוסח (`CONSENT_VERSION` ב-[server/src/app.ts](server/src/app.ts)). הנוסח ב-`#/legal` הוא **טיוטה להדגמה** וממתין לבדיקה משפטית.

## מה עוד לא קיים

- **חיבור Gmail:** לאיסוף קבלות מהמייל.
- **התחברות עם קוד ב-SMS:** עולה כסף לכל הודעה.
- **ערוצי תזכורת:** מייל, WhatsApp ו-Web Push. כרגע התזכורות רק נכתבות ללוג.
- **מאגר ידע מאומת:** התבניות ב-`knowledge/` הן טיוטות (`verified: false`).
- **מחיקת חשבון ונתונים** מתוך הממשק.
