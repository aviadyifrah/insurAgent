# InsurAgent

כלי עזר מבוסס AI שעוזר לאנשים פרטיים להכין בעצמם תביעות להחזר הוצאות רפואיות. המשתמש מספר איזה טיפול עשה ואיזה ביטוח יש לו, והכלי:

1. בונה רשימת מסמכים נדרשים (מתוך מאגר תבניות לפי חברה וסוג תביעה).
2. בודק את המסמכים שהמשתמש מעלה ומשייך אותם לדרישות. מסמכים מתביעות קודמות, כמו ת"ז ואישור בנק, נשמרים לשימוש חוזר.
3. מה שחסר, הופך למשימה למשתמש (לצלם, לחתום, לשלוח מייל שכבר הוכן) ומזכיר לו עד שהמשימה בוצעה.
4. כשהכול מוכן, בונה במכשיר של המשתמש קובץ PDF להגשה: טופס פרטי תביעה חתום וכל המסמכים.

**המשתמש מגיש ושולח הכול בעצמו.** הכלי לא מגיש, לא מייצג, לא מעריך סכומי החזר ולא קובע מה מכוסה.

## הרצה

דרישות: Node 22.

```bash
npm install
cp server/.env.example server/.env   # להכניס ANTHROPIC_API_KEY
npm run dev                          # שרת על 8787 + אתר על 5173
```

פותחים את http://localhost:5173. בנייד פותחים את הכתובת ברשת המקומית ש-Vite מדפיס.

### הדגמה

`npm run samples -w server` יוצר בתיקייה `samples/` ארבעה מסמכים בדויים: קבלה, פירוט טיפולים, ת"ז ואישור בנק. כולם מסומנים "לדוגמה בלבד", כך שאפשר להדגים תביעה מלאה בלי מידע אמיתי. הסוכן מזהה שאלה מסמכי דוגמה, וימשיך רק אם אומרים לו שזו הדגמה.

## איפה נשמר מה

| מידע | איפה |
|---|---|
| קבצי המסמכים והחתימה | **במכשיר של המשתמש** (IndexedDB), מאחורי ממשק `DocumentStore` שאפשר להחליף |
| תוכן המסמך בזמן העלאה | עובר פעם אחת בשרת ובשירות ה-AI לצורך חילוץ פרטים, ולא נכתב לדיסק |
| פרטים שחולצו מהמסמכים, פרטי תביעה, פרופיל, צ'אט, משימות | בשרת (SQLite) |
| חבילת ה-PDF להגשה | נבנית בדפדפן מהקבצים שבמכשיר |

**המגבלות של אחסון במכשיר:** החלפת מכשיר או ניקוי נתוני הדפדפן מוחקים את הקבצים. באייפון Safari עלול למחוק אחסון של אתרים שלא נכנסו אליהם זמן מה. אם קובץ חסר, הממשק מציג "לא שמור במכשיר הזה" ומבקש להעלות אותו שוב.

כדי להוסיף אחסון בשרת או אחסון משולב, מממשים `DocumentStore` חדש ב-[web/src/documentStore.ts](web/src/documentStore.ts) ומוסיפים ערך לעמודה `storage` בשרת.

## מבנה

```
shared/                 רינדור PDF עברי (RTL), משמש את הדפדפן ואת השרת
server/                 Node + Hono + SQLite (node:sqlite)
  src/agent/            לולאת הסוכן (Claude Opus 5.5 + tool use), הכלים, ה-system prompt וחילוץ מסמכים
  src/claims.ts         משימות, תזכורות ומצב התביעה שהסוכן רואה בכל תור
  src/reminders.ts      לולאת התזכורות (כרגע הדפסה לקונסול)
  knowledge/            תבניות דרישות לפי חברה וסוג תביעה (JSON)
  scripts/              יצירת מסמכי דוגמה
web/                    React + Vite, RTL, מותאם לנייד (PWA)
```

## איך הסוכן עובד

- כל תביעה היא שיחה. ההיסטוריה נשמרת ב-`agent_turns` ונשלחת למודל כמו שהיא, בלי עריכה.
- מסמך שהועלה מגיע לסוכן כ-`<uploaded_document>` עם הפרטים שחולצו ממנו, ולא כקובץ.
- בכל תור נשלח למודל `<claim_state>` עם מצב התביעה העדכני.
- פעולות של המשתמש במסכים (העלאה, חתימה, "שלחתי") מגיעות לסוכן כ-`<app_event>`.
- התזכורות לא עוברות דרך המודל: יש לוח זמנים קבוע (1, 3, 7 ימים ואז כל שבוע).
- ה-API מוגדר עם fallback אוטומטי בצד השרת (`fallbacks: "default"`): אם המודל דוחה בקשה מסיבות בטיחות, הבקשה רצה שוב על מודל חלופי.

## הסכמה ותנאים

כניסה ראשונה מחייבת אישור של תנאי השימוש ומדיניות הפרטיות. האישור נשמר עם גרסת הנוסח (`CONSENT_VERSION` ב-[server/src/index.ts](server/src/index.ts)), ושינוי הגרסה מבקש מכל המשתמשים לאשר מחדש. הנוסח ב-`#/legal` הוא **טיוטה להדגמה** וממתין לבדיקה משפטית.

## מה עוד לא קיים

- **התחברות אמיתית:** כרגע כניסת פיתוח עם מייל בלבד. צריך Google Sign-In או קוד ב-SMS.
- **חיבור Gmail:** הכלי `search_email` מחזיר "לא מחובר".
- **ערוצי תזכורת:** מייל, WhatsApp ו-Web Push. כרגע התזכורות רק מודפסות לקונסול.
- **מאגר ידע מאומת:** התבניות ב-`knowledge/` הן טיוטות (`verified: false`).
- **מחיקת חשבון ונתונים** מתוך הממשק.
